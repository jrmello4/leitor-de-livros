# Issues #7–#10 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the four currently unblocked tickets—tactile page turns, safe custom covers, profile transfer with preview/undo, and keyboard-complete navigation/bookmarks—then verify, push, and close only #7–#10.

**Architecture:** Keep pure contracts in `src/domain`, use the existing browser/native adapter boundary for durable state, and let `App` coordinate cross-component state. `ReaderView` owns visual page-turn phases but registers one stable request function so every navigation source shares the same transition path. Native custom covers are derived cache artifacts backed by private source metadata; browser covers use bounded local storage data URLs.

**Tech Stack:** React 19, TypeScript 5.9, Vitest/jsdom, Vite, Tauri 2, Rust, SQLite, `image` crate, GitHub CLI.

## Global Constraints

- No implementation of #11 or #12.
- Do not modify or delete imported publication sources, page bytes, or original cover files.
- Profile transfers contain only named-profile preferences; never library history, progress, bookmarks, diagnostics, paths, or cache state.
- No new external runtime dependency for frontend testing.
- Use TDD: write each failing test, observe the failure, implement the smallest passing change, then refactor.
- Run frontend tests/build, Rust formatting/Clippy/tests, and `git diff --check` before claiming completion.

## File Map

- `src/domain/pageTurn.ts`: framework-independent page-turn decision contract.
- `src/domain/covers.ts`: cover metadata validation and publication-cover fallback.
- `src/domain/profiles.ts`: versioned profile transfer, validation, merge, and preview-safe updates.
- `src/domain/input.ts` and `src/domain/types.ts`: action and custom-cover model contracts.
- `src/services/storage.ts`, `src/services/covers.ts`, `src/services/nativeLibrary.ts`, `src/services/readerState.ts`: browser/native persistence adapters.
- `src/app/App.tsx`, `src/app/ReaderView.tsx`, `src/app/PageNavigator.tsx`, `src/app/LibraryView.tsx`, `src/app/ProfilePanel.tsx`: user-facing coordination and controls.
- `src/app/styles.css` and `src/i18n/catalog.ts`: transition, cover, focus, and copy support.
- `src-tauri/src/models.rs`, `src-tauri/src/db.rs`, `src-tauri/src/lib.rs`: native custom-cover schema, safe file operations, and commands.

**Interfaces:**
- `CustomCover = { src: string; sourceName: string }` is optional on `Publication` and contains no original native source path.
- `validateCoverMetadata(name, mimeType, byteSize)` accepts image MIME/extensions up to `10 * 1024 * 1024` bytes and returns a localized-safe error key.
- Browser adapters expose `loadCustomCover`, `saveCustomCover`, and `clearCustomCover` keyed by publication ID; `readBrowserCover(file)` returns a bounded `CustomCover` data URL.
- Native adapters expose `chooseNativeCover()`, `setNativeCover(publicationId, sourcePath)`, and `clearNativeCover(publicationId)`; the frontend receives only a derived cache path converted with `convertFileSrc`.

  expect(validateCoverMetadata('cover.png', 'image/png', 10 * 1024 * 1024 + 1).ok).toBe(false);

  expect(loadCustomCover('book-1')).toEqual(cover);
  clearCustomCover('book-1');
  expect(loadCustomCover('book-1')).toBeUndefined();
});
